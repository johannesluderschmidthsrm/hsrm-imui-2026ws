Checkliste KimPim Qualitätssicherung

  • HTML-Seite heißt <index.html>?
  • HTML, CSS, JS-Code aufgeräumt?Unnötige Fragmente und Kommentare entfernen. Klassen, die nicht angewendet werden, entfernen. Nicht verwendete Libaries, Schriften und Scripte entfernen. Sinnvolle Umbrüche. In CSS sollte zusammengehöriges auch zusammen stehen.
  • Dateien aufgeräumt? Nicht verwendete Bilder und Testdateien entfernen! Im Ordner sollten nur die auch wirklich in der Website verwendeten Dateien sowie die Git-Dateien (z.B. .git, .github und .gitignore) liegen.
  • Code im W3C Validator geprüft und alle Fehler beseitigt? Ggf. VS-Code-Plugin verwenden.
    Fehlermeldungen wegen verschachtelten CSS sollen ignoriert werden!
    uiKit-HTML-Attributte von uk-... in data-uk-... umbenennen.
  • Nur eine <h1> auf der Seite? Die Hauptabschnitte sollten eine <h2> haben, die darunter eine <h3>, usw.
  • Alle Ids nur jeweils einmal auf der Seite verwendet? Alle Id-Namen ohne Leerzeichen und Sonderzeichen? Ggf. Suchfunktion verwenden
  • Bei Allen Bildern sinnvolle alt-Attribute gesetzt?
  • Keine Inlinestyles im HTML-Code? Einzige Ausnahme: Hintergrundbilder bzw. Farben, die nur ein einziges Mal vorkommen.
  • CSS-Einbindung im <head>, JavaScript-Einbindungen gesammelt vor dem <body>? Keine Doppeleinbindungen (z.B. jeweils nur eine Version von jQuery und UIkit)
  • Passende Web-Bildformate verwendet?
    • SVG für Logos, Icons und andere Vektorgrafiken
    • JPG oder WebP für Photos
    • PNG bzw. WebP (bessere Kompimierung) für Bilder mit Transparenz
  • Alle Bilder runtergrechnet und komprimiert? Pixelabmessungen maximal so groß wie die größte Anzeigegröße. Große Bilder max. 2560px Breite. Keine Bilder über 1MB! Wenn wir trotz aller Hinweise immer noch solche Riesenbilder in ihren Daten finden gibt das Punktabzug!
  • Alle Schriften als Webfonts eingebettet?Die Einbindung sollte mittels @import oder @font-face am Anfang der CSS-Datei geschehen, nicht in HTML
  • Bei font-family in CSS immer einen Fallback-Font angegeben (z.B. sans-serif)?
  • Keine Texte in Großbuchstaben im HTML-Quelltext? Versalschrift sollte immer mit CSS (text-transform:uppercase) erzeugt werden
  • Code erfolgreich auf Github gepushed? Grüner Haken in den Github Actions? Oder gibt es dort beim letzten Commit einen Fehler?
    Bei Problemen bitte melden!
  • Website auf dem Testserver getestet?
  • Auch auf dem Smartphone? Funktionieren alle Hover-Funktionen on Tab?
  • Website auf Chrome und Firefox getestet?In diesen Browsern findet die Präsentation und Bewertung statt.
  • Gibt es in der Browser Konsole JavaScript-Fehler?Fehler müssen alle korrigiert werden, Warnungen sind tolerierbar.
  • Gibt es im Netzwerkpanel Ladefehler?
  • Website auf unterschiedlichen Auflösungen und Endgeräte getestet? Beamer im Präsentationsraum hat vermutlich die Auflösung 1920*1200px. Auch eine Smartphone-Ansichts sollte präsentiert werden.
  • Taucht ungewolltes horizontales Scrollen auf? Falls ja: In den Dev-Tools durch abschnittsweise Sections entfernen bis der Verursacher gefunden wurde und dann ggf. mit overflow:hidden; reparieren.
  • Beipackzettel verfassen und in der readme.md im Git-Ordner speichern: Welcher Fremdcode wurde verwendet (Link Quelle)? Welche fremden Bilder, Videos oder Texte?
